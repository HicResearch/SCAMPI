DICOM metadata
extraction, simplified

SCAMPI pulls DICOM files from a filesystem or PACS server, extracts their metadata into SQL Server, and optionally anonymises tags, detects burned-in text, and archives files — all from a single config file.

What it does
📂

Flexible sources

Read DICOM files from a local directory or pull studies from any PACS via C-MOVE. Supports .7z and .zip archives.

🗄️

Metadata to SQL

Extracts DICOM tags per modality using configurable .it templates and writes rows to SQL Server.

🔏

Anonymisation

Remove, replace, date-jitter, or randomise patient identifiers using a built-in HIPAA Safe Harbor profile or custom rules.

👁️

OCR check

Scan pixel data for burned-in text using Tesseract OCR. Flags files and records a BurnedInTextDetected column in the database.

🗜️

7z archiving

Optionally pack output files into daily or hourly .7z archives using maximum LZMA2 compression.

🐳

Docker-native

Ships as a single Docker image. Everything is configured via a mounted config.yml — no code changes needed.

Quick start

Get up and running in three steps

  1. Create a config file
    Use the Config Wizard to generate a config.yml, or copy the sample from the repository and edit it by hand.
    shell
    cp processing_engine/sample_config.yml config.yml
# then edit config.yml for your environment
  2. Build the Docker image
    Run from the repository root. Tesseract OCR and all Python dependencies are included.
    shell
    docker build -t scampi -f processing_engine/Dockerfile processing_engine/
  3. Run the container
    Mount your config, DICOM source, output directory, modality templates, and (optionally) a logs directory.
    shell
    docker run --rm \
  -v /path/to/config.yml:/config.yml \
  -v /path/to/dicoms:/my_images \
  -v /path/to/output:/output \
  -v /path/to/templates:/templates \
  -v /path/to/logs:/SCAMPI/logs \
  scampi
    On Windows, use forward slashes: C:/Users/you/config.yml:/config.yml

Volume mounts

Host → Container Required? Purpose
config.yml:/config.yml Required Your SCAMPI configuration file.
/dicoms:/my_images Filesystem sources Source directory for DICOM files. Must match directory in config. Not needed for PACS-only setups.
/output:/output Required Where processed files (or .7z archives) are written. Must match destination.files.directory.
/templates:/templates Required Directory of .it modality template files defining which DICOM tags to extract per modality. See DicomTypeTranslation.
/logs:/SCAMPI/logs Optional Persists structured JSON log files to the host. Logs are also printed to stdout.

Configuration reference

All options are set in config.yml. Use the Config Wizard to generate one interactively.

Sources
sources:
  my_files:                      # arbitrary label
    type: filesystem
    directory: /my_images        # path inside the container
    file_regex: .*               # optional filename filter
    include_archives: true       # also process .7z / .zip archives

  my_pacs:
    type: pacs
    aet: SCAMPI                  # calling AE title
    aec: ORTHANC                 # called AE title (PACS)
    aem: SCAMPI                  # move destination AE title
    ip: 192.168.1.10
    port: 4242
    store_port: 11113            # port SCAMPI listens on for C-STORE
    keys:
      - "QueryRetrieveLevel=STUDY"
Anonymisation
anonymisation:
  enabled: true
  profile: basic                 # "basic" removes standard HIPAA identifiers
  tags:                          # optional per-tag overrides
    - tag: PatientName
      action: random_name        # replace | remove | random_name | jitter
    - tag: PatientBirthDate
      action: jitter
      days: 90                   # shift date by ±90 days
OCR
ocr:
  enabled: true
  max_frames: 1                  # frames to check per multi-frame DICOM
Destination
destination:
  files:
    directory: /output
    archive:
      enabled: true              # pack files into .7z archives
      group_by: day              # day | hour
  metadata:
    dbType: MSSQL
    connectionString: mssql+pyodbc://user:pass@host.docker.internal,1433/DB?driver=ODBC+Driver+18+for+SQL+Server&TrustServerCertificate=yes
    index: SOPInstanceUID        # primary key column
